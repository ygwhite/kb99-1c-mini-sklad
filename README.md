# Мини-Склад

Учебный проект первой недели стажировки «1С Старт с нуля».
Задание: https://github.com/phsin/kb99-1c-start/blob/main/week1.md

## Назначение

Минимальная конфигурация для оформления поступления и реализации товаров
и регистрации приходных и расходных движений.

## Состав конфигурации

| Объект | Назначение |
| --- | --- |
| Подсистема `МиниСклад` | Раздел интерфейса «Мини-Склад» |
| Справочник `Товары` | Список товаров |
| Справочник `Контрагенты` | Список поставщиков и покупателей |
| Документ `Поступление` | Оформление поступления товаров; движения с видом «Приход» |
| Документ `Реализация` | Оформление продажи товаров; движения с видом «Расход» |
| Регистр накопления `ОстаткиТоваров` | Учёт количества товаров; вид регистра — «Остатки» |

Документы содержат реквизит `Контрагент` и табличную часть `Товары`
с колонками `Товар`, `Количество`, `Цена`, `Сумма`.
В формах настроен пересчёт суммы строки при изменении количества или цены.

В регистре `ОстаткиТоваров` используется измерение `Товар`
и ресурс `Количество`. Движения создаются при проведении документов.

## Требования

- Платформа «1С:Предприятие» 8.5 с Конфигуратором.
- Для учебной работы используется файловая информационная база.

Разработка ведётся в учебной версии платформы на macOS.
Работа на других версиях платформы отдельно не проверялась.

## Файлы репозитория

- `src/` — выгрузка конфигурации в XML-файлы, включая модули на встроенном языке.
- `README.md` — описание проекта, порядок загрузки и проверки.
- `.gitignore` — исключения для файлов базы, резервных копий и временных файлов.

Данные информационной базы в `src/` не входят. Товары, контрагенты
и документы для проверки создаются после загрузки конфигурации.

## Как открыть проект с нуля

1. Скачайте репозиторий и распакуйте архив либо клонируйте его через Git.
2. Запустите окно выбора информационных баз «1С:Предприятия».
3. Нажмите «Добавить» и выберите создание новой информационной базы.
4. Выберите создание базы без конфигурации для разработки новой конфигурации.
5. Укажите имя базы и отдельную пустую папку для файлового варианта.
6. Откройте созданную базу в режиме «Конфигуратор».
7. Выполните «Конфигурация → Открыть конфигурацию».
8. Выполните «Конфигурация → Загрузить конфигурацию из файлов…»
   и выберите папку `src` из репозитория.
9. Сохраните конфигурацию и выполните
   «Конфигурация → Обновить конфигурацию базы данных».
   Подтвердите изменения структуры, если появится соответствующее окно.
10. Запустите приложение через «Отладка → Начать отладку».
11. Откройте раздел «Мини-Склад» и создайте данные для проверки.

## Сценарий проверки перед сдачей

Для проверки используйте новый товар, по которому ещё нет движений.

1. Создайте в справочнике `Товары` элемент «Тестовый товар».
2. Создайте контрагентов «Поставщик» и «Покупатель».
3. Создайте `Поступление`: контрагент «Поставщик», товар «Тестовый товар»,
   количество 10, цена 100. Ожидаемая сумма строки — 1000.
4. Проведите поступление. Ожидается движение «Приход» на 10 единиц.
5. Создайте `Реализация`: контрагент «Покупатель», тот же товар,
   количество 3, цена 150. Ожидаемая сумма строки — 450.
6. Проведите реализацию. Ожидается движение «Расход» на 3 единицы.
7. Проверьте записи регистра: регистраторы должны соответствовать документам,
   товар и количество — строкам документов. Ожидаемый остаток после обеих
   операций — 7 единиц.
8. Повторно проведите те же документы и проверьте, что движения не дублируются.

## Статус проверки

Итоговая проверка по сценарию выше ещё не выполнена.
Перед сдачей необходимо подтвердить проведение обоих документов,
корректность движений и загрузку конфигурации в новую пустую базу.

## Обновление исходников

После изменения конфигурации выполните
«Конфигурация → Выгрузить конфигурацию в файлы…».
Выберите XML-файлы и папку `src` этого репозитория.
Перед коммитом просмотрите изменения и убедитесь, что в репозиторий
не попали файлы рабочей информационной базы.
